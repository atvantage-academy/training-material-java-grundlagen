Kontoarten polymorph behandeln

Kontoarten polymorph behandeln

Als Entwickler:in möchte ich Konten unterschiedlicher Art einheitlich behandeln und trotzdem das jeweils richtige Verhalten auslösen, damit neue Kontoarten die bestehende Abhebe-Logik nicht anfassen müssen.

Lernziele

Die Lernenden…

  • überschreiben eine geerbte Methode in einer Unterklasse mit @Override.
  • arbeiten über eine Basisklassen-Referenz und erklären die dynamische Bindung.
  • verarbeiten eine List<Account> einheitlich.

Definition of Done

  • Account besitzt eine Methode isAmountAvailable(Money), die withdraw nutzt.
  • CurrentAccount überschreibt isAmountAvailable, sodass der Dispositionskredit berücksichtigt wird.
  • Eine List<Account> mit Giro- und Sparkonto wird in einer Schleife einheitlich abgefragt.
  • Der Abhebe-Versuch verhält sich je Kontoart korrekt unterschiedlich.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Verfügbarkeitsprüfung in der Basisklasse

Gib Account eine Methode isAmountAvailable(Money amount), die standardmäßig nur den Saldo prüft, und nutze sie in withdraw.

Hinweis: withdraw bleibt in der Basisklasse – es ruft nur isAmountAvailable(...) auf. Genau darüber greift später die Polymorphie.

Verhalten im Girokonto überschreiben

Überschreibe isAmountAvailable in CurrentAccount, sodass zusätzlich der Dispositionskredit zählt.

@Override
protected boolean isAmountAvailable(Money amount) {
  // verfügbar = Saldo + Dispolimit
  return getBalance().plus(limit).isGreaterOrEqual(amount);
}

Hinweis: SavingsAccount überschreibt nichts – es erbt die strengere Standardprüfung. Auch das ist eine bewusste Entwurfsaussage.

Einheitlich über den Basistyp arbeiten

Lege beide Konten in eine List<Account> und versuche in einer Schleife, denselben Betrag abzuheben.

Reflexionsfragen

  • Warum musst Du withdraw nicht ändern, obwohl sich das Verhalten je Kontoart unterscheidet?
  • Was müsstest Du für eine neue Kontoart (z. B. „Festgeld“) tun – und was ausdrücklich nicht?
  • Wo liegt der Unterschied zwischen dem deklarierten Typ (Account) und dem tatsächlichen Typ (CurrentAccount) beim Methodenaufruf?
