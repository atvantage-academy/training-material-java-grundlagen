Fehlerfälle mit Ausnahmen behandeln

Als Entwickler:in möchte ich, dass eine unmögliche Abhebung nicht stillschweigend passiert, sondern klar signalisiert wird, damit aufrufender Code den Fehler bewusst behandeln muss.

Lernziele

Die Lernenden…

  • definieren eine eigene Exception-Klasse.
  • werfen eine Ausnahme an der passenden Stelle und behandeln sie mit try/catch.
  • begründen, ob eine Ausnahme checked oder unchecked sein sollte.

Definition of Done

  • Es gibt eine Exception InsufficientFundsException (checked).
  • withdraw wirft diese Exception, wenn der Betrag nicht verfügbar ist.
  • Der Aufrufer in Main fängt die Exception mit try/catch und gibt eine sinnvolle Meldung aus.
  • Ein Programmierfehler (z. B. null-Betrag) wird über eine unchecked Exception abgelehnt.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Eine fachliche Exception definieren

Lege eine checked Exception an (erbt von Exception).

public class InsufficientFundsException extends Exception {
  public InsufficientFundsException(String message) {
    super(message);
  }
}

Hinweis: „Checked” = erbt von Exception (nicht RuntimeException). Der Compiler erzwingt dann die Behandlung.

Die Ausnahme werfen

Lass withdraw die Ausnahme werfen, wenn isAmountAvailable false liefert. Deklariere sie mit throws.

Hinweis: Prüfe zuerst die Vorbedingung; erst wenn sie erfüllt ist, verändere den Saldo — sonst bleibt das Konto im gültigen Zustand.

Den Fehler behandeln

Rufe withdraw in Main in einem try/catch auf und reagiere sinnvoll.

try {
  account.withdraw(Money.euro(100));
} catch (InsufficientFundsException e) {
  System.out.println("Abhebung nicht möglich: " + e.getMessage());
}

Reflexionsfragen

  • Warum ist „unzureichendes Guthaben” eine checked, ein null-Argument aber eine unchecked Exception?
  • Was wäre der Nachteil, den Fehlerfall über einen boolean-Rückgabewert zu lösen?
  • Wozu dient finally, und was gehört dort typischerweise hinein?
