Prozedurale Logik nach Java übertragen

Prozedurale Logik nach Java übertragen

Als Umsteiger:in möchte ich vertraute Konstrukte wie Variablen, Schleifen und Methoden in Java schreiben, damit mir die Syntax für den Rest der Woche flüssig von der Hand geht.

Hinweis: Die Visualisierung Java-Syntax auf einen Blick (rechts unter „Weiterführende Informationen“) fasst Datentypen, Schreibweisen, Typumwandlung, Methoden und Kontrollstrukturen zum Nachschlagen zusammen. Hier steht bewusst keine fertige Lösung – schreib den Code selbst und schlag nach, wenn Du hängst.

Lernziele

Die Lernenden…

  • schreiben eine Methode mit Parametern und Rückgabewert und rufen sie auf.
  • nutzen eine Schleife und eine Bedingung, um über ein Array zu laufen.
  • benennen die Signatur einer Methode und überladen sie.
  • erklären, warum die Division zweier int-Werte nicht den erwarteten Durchschnitt liefert, und setzen den Cast an der richtigen Stelle.
  • geben Ergebnisse mit System.out.println(…) aus.

Definition of Done

  • Es gibt eine Methode, die ein int[] entgegennimmt und den Durchschnitt seiner Werte als double zurückgibt.
  • Es gibt eine zweite, überladene Methode gleichen Namens mit einem zusätzlichen Parameter: Sie liefert diesen Wert zurück, wenn das Array leer ist.
  • Eine Schleife und eine Bedingung kommen sinnvoll zum Einsatz.
  • main ruft beide Varianten auf – auch einmal mit einem leeren Array – und gibt die Ergebnisse aus.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Den Durchschnitt berechnen

Schreibe eine statische Methode, die ein int[] entgegennimmt und den Durchschnitt seiner Werte zurückgibt. Überleg Dir zuerst, welchen Rückgabetyp das Ergebnis braucht – der Durchschnitt ganzer Zahlen ist selten wieder eine ganze Zahl.

Hinweis: Die Anzahl der Elemente liefert values.length – beim Array ohne Klammern, anders als length() beim String. Über die Elemente kommst Du mit einer klassischen for-Schleife oder mit for-each.

Achtung, Stolperstein: Teilst Du zwei int-Werte, rechnet Java ganzzahlig und schneidet den Rest ab – 7 / 2 ergibt 3, nicht 3.5. Probiere es zuerst falsch aus, sieh Dir das Ergebnis an und setze dann den Cast an der Stelle, an der er wirkt.

Den leeren Sonderfall behandeln

Was passiert, wenn das Array leer ist? Probiere es aus und sieh Dir an, was Dein Programm tut. Fange den Fall dann mit einer Bedingung ab.

Die Methode überladen

Schreibe eine zweite Methode mit demselben Namen, die zusätzlich einen Standardwert entgegennimmt. Ist das Array leer, gibt sie diesen Wert zurück, sonst den berechneten Durchschnitt.

Hinweis: Beide Methoden heißen gleich und unterscheiden sich nur in der Parameterliste – genau das ist Überladen. Ein anderer Rückgabetyp allein würde dafür nicht genügen. Ruf am Ende die eine Variante aus der anderen auf, statt die Berechnung zu kopieren.

Die Ergebnisse ausgeben

Ruf beide Varianten in main auf – mit einem gefüllten und mit einem leeren Array – und gib die Ergebnisse aus.

Hinweis: Ausgaben schreibst Du mit System.out.println(…); die Variante System.out.print(…) verzichtet auf den Zeilenumbruch. Mit + hängst Du Text und Werte aneinander: System.out.println("Durchschnitt: " + schnitt);

Für Schnelle: einmal im Debugger anhalten

Setze in Deiner Methode einen Breakpoint (Klick links neben die Zeilennummer), starte das Programm über Debug statt Run und geh mit Step Over Zeile für Zeile durch die Schleife. Beobachte, wie sich Summe und Zähler verändern.

Hinweis: Das ist hier nur ein erster Blick auf das Werkzeug – ausführlich kommt das Debugging später an der Reihe.

Reflexionsfragen

  • Was gehört zur Signatur einer Methode – und wodurch unterscheiden sich zwei überladene Methoden?
  • Warum liefert die Division zweier int-Werte nicht den erwarteten Durchschnitt – und wo genau muss der Cast stehen, damit er hilft?
