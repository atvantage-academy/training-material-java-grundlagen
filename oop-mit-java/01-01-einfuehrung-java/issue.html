Die Java-Plattform erkunden

Die Java-Plattform erkunden

Als Umsteiger:in möchte ich sehen, was zwischen meinem Quellcode und der laufenden Anwendung passiert, damit ich verstehe, warum dasselbe Java-Programm auf jedem Betriebssystem läuft.

Lernziele

Die Lernenden…

  • kompilieren eine vorgegebene .java-Datei mit javac zu einer .class-Datei.
  • betrachten den erzeugten Bytecode mit javap und ordnen die Rolle der JVM ein.
  • erklären am Beispiel das Prinzip „Write once, run anywhere”.

Definition of Done

  • Die vorgegebene Klasse HelloWorld liegt als Datei HelloWorld.java vor.
  • Die Klasse ist mit javac zu einer .class-Datei kompiliert.
  • Du hast Dir den Bytecode mit javap -c angesehen.
  • Das Programm läuft mit java HelloWorld und gibt „Hello, World!” aus.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Die vorgegebene Klasse anlegen

Übernimm den folgenden Quellcode unverändert in eine Datei HelloWorld.java.

public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}

Hinweis: Der Dateiname muss zum Klassennamen passen (HelloWorld.java → class HelloWorld).

Kompilieren und den Bytecode ansehen

Übersetze die Datei und wirf einen Blick auf den erzeugten Bytecode.

javac HelloWorld.java
javap -c HelloWorld

Hinweis: javap -c zeigt den plattformunabhängigen Bytecode — genau das, was die JVM ausführt (nicht Maschinencode Deiner CPU).

Ausführen

Starte das Programm über die JVM.

java HelloWorld

Reflexionsfragen

  • Warum liegt zwischen Deinem Quellcode und der Ausführung überhaupt ein Kompilierschritt?
  • Wieso ist der Bytecode auf jedem Betriebssystem gleich, das Ergebnis aber dennoch überall lauffähig?
  • Wozu brauchst Du beim Entwickeln das JDK, obwohl zum reinen Ausführen die JVM genügt?
