Einen gemeinsamen Vertrag per Interface einführen

Einen gemeinsamen Vertrag per Interface einführen

Als Entwickler:in möchte ich alles, was eine fachliche ID besitzt, über einen gemeinsamen Vertrag ansprechen, damit ich Hilfscode einmal schreibe und für Kunde und Konto gleichermaßen nutze.

Lernziele

Die Lernenden…

  • definieren ein Interface und implementieren es in mehreren Klassen.
  • schreiben eine Methode, die gegen das Interface statt gegen eine konkrete Klasse arbeitet.
  • grenzen Interface und abstrakte Klasse gegeneinander ab.

Definition of Done

  • Es gibt ein Interface Identifiable mit einer Methode getId().
  • Customer und Account implementieren Identifiable.
  • Es gibt eine Methode, die ein Identifiable entgegennimmt und dessen ID nutzt (z. B. describe(Identifiable)).
  • Der Aufruf funktioniert mit Customer- und Account-Objekten.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Das Interface definieren

Lege ein Interface an, das den Vertrag „hat eine ID” beschreibt.

public interface Identifiable {
  String getId();
}

Hinweis: Ein Interface beschreibt nur was möglich ist, nicht wie. Es enthält (klassisch) keine Felder und keine Implementierung.

Den Vertrag implementieren

Lass Customer und Account Identifiable implementieren und getId() passend zurückgeben.

Hinweis: Falls die IDs unterschiedliche Typen haben (UUID vs. IBAN), liefere sie hier einheitlich als String.

Gegen das Interface programmieren

Schreibe eine Methode, die ein Identifiable annimmt — nicht einen konkreten Typ.

static void describe(Identifiable item) {
  System.out.println("Objekt mit ID: " + item.getId());
}

Reflexionsfragen

  • Warum kann describe mit Kunden und Konten umgehen, ohne deren konkrete Klasse zu kennen?
  • Wann würdest Du statt eines Interfaces eine abstrakte Klasse wählen?
  • Welche künftige Erweiterung wird durch „Programmieren gegen das Interface” einfacher?
